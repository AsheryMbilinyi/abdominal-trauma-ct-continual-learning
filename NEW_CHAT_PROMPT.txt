## Context

I am working on a MICAD 2026 paper titled:
"Mitigating Catastrophic Forgetting in CT-Based Abdominal-Trauma Detection:
A Comparison of EWC, Experience Replay, and Their Combination"

The paper studies continual learning on the RSNA 2023 Abdominal Trauma Detection dataset.
The existing GitHub repo implements 4 continual learning methods (Baseline, EWC, Replay,
EWC+Replay) across two experimental settings:
- Class-incremental (CI): Task 1 = class 0 only, Task 2 = class 1 only, shared softmax head
- Domain-incremental (DI): 3 CT window tasks (Brain WL=40/WW=80, Lung WL=-600/WW=1500,
  SoftTissue WL=50/WW=400), both classes per task

================================================================================
REVIEWER COMMENTS
================================================================================

Reviewer 1:
Given the large difference between the reported runs, particularly for Replay, multi-seed
experiments are needed to determine whether the conclusions about EWC, Replay and LwF are
stable. The authors should also distinguish more carefully between catastrophic forgetting
and failure to learn the original or new task, especially when performance remains near
chance. The class-incremental use of a shared softmax head may itself produce label
competition, so comparisons with separate heads or a multi-label formulation would
strengthen the interpretation.

Reviewer 2:
The current evidence is still somewhat preliminary. Most experiments use a single seeded
run, while the differences between Run A and Run B suggest considerable instability. Please
repeat the main comparisons with several seeds and report mean values with standard
deviations or confidence intervals. It would also be useful to include a joint-training
upper bound and a separate-head baseline, so that the effect of continual learning can be
separated from the conflict introduced by the shared classifier.

KEY DESIGN OF EACH NEW EXPERIMENT
================================================================================

multi_seed_ci.py:
  - Seeds: [42, 123, 456] (configurable via SEEDS env var)
  - Methods: Baseline, EWC, Replay, LwF, EWC+Replay
  - Config: MAX_PER_CLASS=30, MAX_PER_PATIENT=5, ITERS_PER_TASK=200,
            FISHER_SAMPLES=100, BUFFER_SIZE=100
  - Outputs per-task accuracy (T1, T2) plus mean +/- std across seeds
  - Supports DEBUG_RUN=1, DATA_DIR, LOG_DIR env vars

joint_training_upper_bound.py:
  - CI: trains on class 0+1 simultaneously, evaluates per class
  - DI: ConcatDataset of 3 CT windows, evaluates per window
  - Config: MAX_PER_CLASS=30, MAX_PER_PATIENT=5, EPOCHS=5
  - Supports DEBUG_RUN=1, DATA_DIR, LOG_DIR env vars

separate_head_baseline.py:
  - MultiHeadCNN: shared backbone + per-task Linear(256->2) heads, frozen after each task
  - SharedHeadCNN: same backbone + single shared head (existing design)
  - Oracle evaluation uses task ID to select correct head
  - Config: MAX_PER_CLASS=30, MAX_PER_PATIENT=5, ITERS_PER_TASK=200
  - Supports DEBUG_RUN=1, DATA_DIR, LOG_DIR env vars

near_chance_analysis.py:
  - Runs all 5 CL methods, scans entries where final_acc <= 55%
  - Runs fresh solo model for near-chance entries
  - Verdicts: OK / Forgetting / CL Failure / Task Unlearnable
  - Covers both CI and DI settings
  - CHANCE_THRESHOLD configurable via env var (default 55%)
  - Supports DEBUG_RUN=1, DATA_DIR, LOG_DIR env vars
